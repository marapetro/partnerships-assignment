## Roadmap (not in 6-week scope)
- **Partner detection inside the sellers' existing AI meeting follow-up skill\*** (Claude via Salesforce MCP, or Claude/Slackbot in Slack).
  - **Deterministic step:** query meeting attendees (Gong / calendar) and match email domains to Partner Accounts / partner Contacts.
  - **Fuzzy step:** Claude reads the transcript to classify Influence Type (intro, technical validation, procurement, exec meeting).
  - **Output:** skill **proposes** Partner Involvement record(s) and pre-answers *Partner Involved?*; **AE confirms before any write** to Salesforce.
  - Embedded in the existing skill, **not mandated** as a gate — the Yes/No attestation (#17) remains the control; Salesforce cannot verify a skill ran unless it writes a marker.
  - **Security:** transcripts are untrusted input (prompt-injection risk) → no unconfirmed CRM writes; MCP connection runs **as the AE** (inherits sharing/FLS), not as a broad integration user; data-processing review for sending customer transcripts to an LLM (confidentiality, PII, retention).

\* **Assumption:** sellers already routinely run AI meeting prep/follow-up skills, so this adds a step to an existing habit rather than creating a new one. If not, adoption cost is higher and a background (no-seller-action) variant should be considered instead.
